## 1. Talab (foydalanuvchi so'zlari, aniqlashtirilgan)
1. **Login qilib bo'lgan foydalanuvchi keyin bloklansa** — hozir u bemalol ishlayveradi. To'g'ri: bloklangan zahoti (kechi bilan bir necha soniyada)
   ekranida "Hisobingiz bloklandi" degan xabar chiqsin, **faqat bitta tugma** bo'lsin; tugma bosilsa tizimdan chiqarib yuborsin.
2. **Avvaldan bloklangan foydalanuvchi kirmoqchi bo'lsa** — hozir "Email yoki parol noto'g'ri" deydi. To'g'ri: "Hisobingiz bloklangan" desin.
3. Bloklangan foydalanuvchi chatda ham hech narsa qila olmasin / ola olmasin.

## 3. Nima qilinadi

### 3.1. Backend

**a) `Api/Auth/ApiErrorCodes.cs`** — `public const string AccountBlocked = "ACCOUNT_BLOCKED";` (mijoz matn emas, shu kodga qaraydi).

**b) `Api/Auth/UserStatusCache.cs`** — singleton, `IMemoryCache` (`builder.Services.AddMemoryCache()`), TTL **30 soniya**.
```csharp
public sealed class UserStatusCache(IMemoryCache cache, IServiceScopeFactory scopes)
{
    public async Task<UserStatus?> GetAsync(Guid userId, CancellationToken ct = default) { /* cache.GetOrCreateAsync; null = foydalanuvchi yo'q */ }
    public void Evict(Guid userId) => cache.Remove(Key(userId));
}
```
Qiymatni `scopes.CreateAsyncScope()` → `AppDbContext` → `db.Users.Where(u => u.Id == id).Select(u => (UserStatus?)u.Status).FirstOrDefaultAsync()`.
(Singleton ichida scoped `AppDbContext` ni to'g'ridan-to'g'ri ushlab bo'lmaydi.) `null` ham keshlansin (o'chirilgan foydalanuvchi).

**c) `Api/Auth/AccountStatusMiddleware.cs`** — `Program.cs` da **`UseAuthentication()` dan keyin, `UseRateLimiter()` dan oldin**:
- autentifikatsiya qilingan foydalanuvchi va yo'l `/api/auth` bilan boshlanmasa (`login`, `refresh`, `logout` o'tsin): statusni keshdan oling;
- `null` → `401`; `Active` emas → `403` + JSON `{ "error": "Hisobingiz bloklangan. Batafsil ma'lumot uchun markaz administratoriga murojaat qiling.", "code": "ACCOUNT_BLOCKED" }`;
- aks holda `next`.
`UseCors` `UseAuthentication` dan oldin turibdi, shuning uchun bu javoblarda CORS sarlavhalari bor (brauzer o'qiy oladi).
SignalR: `/hubs/chat/negotiate` tokenni query'dan oladi (`OnMessageReceived`) — autentifikatsiya qilingan bo'ladi, middleware unga ham 403 beradi.

**d) `AuthController.Login`** — tartib:
1. foydalanuvchi topilmadi → 401 umumiy xato;
2. **parol noto'g'ri → 401 umumiy xato** (bloklangan-bloklanmaganini oshkor qilmaydi — email bo'yicha foydalanuvchi bor-yo'qligini aniqlashga yo'l qo'ymaslik uchun);
3. parol to'g'ri, lekin `Status != Active` → `StatusCode(403, new { error = "Hisobingiz bloklangan. Batafsil ma'lumot uchun markaz administratoriga murojaat qiling.", code = ApiErrorCodes.AccountBlocked })`.
`[EnableRateLimiting("LoginBruteForce")]` o'zgarishsiz qoladi.

**e) `AuthController.Refresh`** — tartib: token qatori topilmadi (revoked bo'lsa ham topiladi) → 401; foydalanuvchi yo'q → 401;
**foydalanuvchi bloklangan → 403 + `ACCOUNT_BLOCKED`**; keyin `!existing.IsActive` → 401. (Shuning uchun bloklashda tokenlarni o'chirmasdan **bekor qilish** kerak — 3.1.f.)

**f) `UsersController`**
- `Deactivate`: refresh tokenlarni `ExecuteDeleteAsync` o'rniga bekor qiling:
  `await db.RefreshTokens.Where(t => t.UserId == id && t.RevokedAt == null).ExecuteUpdateAsync(s => s.SetProperty(t => t.RevokedAt, DateTimeOffset.UtcNow), ct);`
  `SaveChangesAsync` **dan keyin** `await accountBlocker.StatusChangedAsync(id)`.
- `Activate` va `Delete`: saqlagandan keyin xuddi shu chaqiriq (kesh yangilansin).
- (Ehtiyot: `Delete` allaqachon tokenlarni o'chiradi — o'sha joyda qoldiring.)

**f2) Rol darajasidagi himoya (majburiy — yuqoridagi 🔴 teshik).** `CanTouchUser` ni rolga sezgir qiling:
`AllOrganization` scope — hammani (o'zidan tashqari, `Deactivate`/`Delete` da mavjud qoida); `MyBranches` — faqat **`BranchScopedAssignableRoles`** ichidagi rollarga ega foydalanuvchilarni
(Operator, Teacher, SupportTeacher, Student, Parent). **`SUPER_ADMIN`, `ADMINISTRATOR`, `DEVELOPER`** rolli foydalanuvchiga filial administratori tegolmasin (403).
Hisobda bir nechta rol bo'lsa — birortasi ruxsat etilmagan bo'lsa rad. Qo'llanadigan joylar: `Update`, `AssignRole`, `Deactivate`, `Activate`, `Delete` (va S01.05 dagi `reset-password`).
Foydalanuvchining rol kodlari uchun `db.UserRoles` + `db.Roles` (`UserDto` allaqachon shunday yig'adi).

**g) `Api/Auth/AccountBlocker.cs`** (scoped) — `StatusChangedAsync(Guid userId)`: `statuses.Evict(userId)`; agar yangi holat `Active` emas — hub'ga xabar (3.1.h).

**h) `Api/Chat/ChatHub.cs`**
- `UserConnections` — `ConcurrentDictionary<Guid, ConcurrentDictionary<string, byte>>` (userId → connectionId'lar); `OnConnectedAsync`/`OnDisconnectedAsync` da yangilang.
- `static async Task DropUserAsync(IHubContext<ChatHub> hub, Guid userId)`: `hub.Clients.Group(UserGroup(userId)).SendAsync("accountBlocked")`,
  so'ng shu foydalanuvchining har bir ulanishi uchun `Subscriptions[connId]` dagi har bir chatdan `hub.Groups.RemoveFromGroupAsync(connId, ChatGroup(chatId))` va `Subscriptions[connId] = []`.
  (Server tomondan ulanishni uzib bo'lmaydi — ammo hamma guruhdan chiqarilgan va metodlari rad etadigan ulanish behuda.)
- `SyncChats` va `Typing` boshida: `if (await statuses.GetAsync(UserId) != UserStatus.Active) throw new HubException(ApiErrorCodes.AccountBlocked);`
  (`ChatHub` konstruktoriga `UserStatusCache` qo'shing).
- `AccountBlocker.StatusChangedAsync` `IHubContext<ChatHub>` orqali `DropUserAsync` ni chaqiradi.

**i)** `Program.cs`: `AddMemoryCache()`, `AddSingleton<UserStatusCache>()`, `AddScoped<AccountBlocker>()`, `app.UseMiddleware<AccountStatusMiddleware>()`.

### 3.2. Frontend
1. **`lib/account-status.ts`** — `useSyncExternalStore` asosidagi kichik do'kon (`lib/use-auth-session.ts` uslubida): `ACCOUNT_BLOCKED_CODE`,
   `markAccountBlocked()`, `clearAccountBlocked()`, `useAccountBlocked(): boolean`.
2. **`lib/api-client.ts`**:
   - `authorizedFetch`: `!response.ok` shoxida `body.code === "ACCOUNT_BLOCKED"` (status 403) bo'lsa `markAccountBlocked()` (xatoni odatdagidek tashlashda davom eting).
   - `refreshAccessToken`: `!response.ok` bo'lsa avval javob tanasini o'qing; **403 + ACCOUNT_BLOCKED** bo'lsa `markAccountBlocked()` va `return false` (**`clearTokens()` chaqirmang** — ekrandagi tugma sessiyani o'zi tozalaydi); boshqa holatda avvalgidek `clearTokens()`.
3. **`lib/chat-hub.ts`**: `created.on("accountBlocked", markAccountBlocked)`; `invoke` xatosi `ACCOUNT_BLOCKED` ni o'z ichiga olsa ham `markAccountBlocked()`.
4. **`components/BlockedScreen.tsx`** — butun ekranni egallovchi (`fixed inset-0`, Drawer/Modal'dan yuqori `z`), `role="alertdialog"`, `aria-modal`, `aria-labelledby/-describedby`:
   - ikonka (`ShieldAlert`), sarlavha **"Hisobingiz bloklandi"**, matn **"Administrator hisobingizni bloklagan, shuning uchun tizimdan foydalanib bo'lmaydi. Savollaringiz bo'lsa markaz administratoriga murojaat qiling."**
   - **faqat bitta tugma** — **"Tizimdan chiqish"** (`autoFocus`); yopish (X), Escape, orqa fonni bosish **yo'q**;
   - tugma `onLogout` ni chaqiradi.
5. **`app/(admin)/layout.tsx`**: hook'lardan keyin, `if (!hydrated) return null;` dan so'ng
   `if (blocked) return <BlockedScreen onLogout={handleLogout} />;` — **sidebar, sahifa va bell umuman render qilinmasin** (shunda fon so'rovlari, polling va fokus ushlanishi to'xtaydi).
   `handleLogout` ga `clearAccountBlocked()` qo'shing (mavjud: `apiLogout`, `stopChatConnection`, `clearTokens`, `router.replace("/login")`).
6. **`app/(auth)/login/page.tsx`**: xato `ApiError` va `(error.body as {code?: string})?.code === ACCOUNT_BLOCKED_CODE` bo'lsa, qizil emas — **ogohlantirish** ko'rinishi
   (`bg-warning-50 text-warning-600`, `ShieldAlert`), sarlavha **"Hisobingiz bloklangan"** + server matni. Boshqa xatolar avvalgidek qizil.

### 3.3. Xatti-harakat jadvali (qabul mezoni)
| Holat | Natija |
|---|---|
| Bloklangan, to'g'ri parol bilan kirmoqchi | 403 `ACCOUNT_BLOCKED` → loginda ogohlantirish |
| Bloklangan, noto'g'ri parol | 401 "Email yoki parol noto'g'ri." (oddiy xato — holat oshkor bo'lmaydi) |
| Tizimda ishlab turgan foydalanuvchi bloklandi | keyingi har qanday so'rov 403 `ACCOUNT_BLOCKED` → ≤ 60 s (yoki keyingi bosishdayoq) to'liq ekran xabar, bitta tugma |
| Tugma bosildi | logout, tokenlar tozalanadi, `/login` |
| Blokdan chiqarildi | yangi login ishlaydi; eski token (muddati tugamagan bo'lsa) ham ishlaydi |
| Chat ochiq edi | `accountBlocked` hodisasi → ekran; server chat guruhlaridan chiqaradi |

## 4. Testlar — `backend/tests/EduCenter.Api.IntegrationTests/AccountBlockingTests.cs` (~9)
1. Login: bloklangan + to'g'ri parol → **403**, `code == "ACCOUNT_BLOCKED"`; noto'g'ri parol → **401** umumiy; mavjud bo'lmagan email → 401 umumiy.
2. Foydalanuvchi kirgan, superadmin `POST /api/users/{id}/deactivate` qiladi → **shu tokenning o'zi** bilan policy'li endpoint (`GET /api/students`) va policy'siz endpointlar
   (`GET /api/me/permissions`, `GET /api/notifications/unread-count`) → 403 + kod. (Kutmasdan — kesh tozalanadi.)
3. `activate` dan keyin xuddi shu token yana ishlaydi; login ham ishlaydi.
4. Bloklashdan keyin `POST /api/auth/refresh` → 403 + kod (tokenlar o'chmagan, bekor qilingan). Oddiy logout'dan keyin refresh → 401.
5. Bloklangan foydalanuvchi `POST /api/auth/logout` qila oladi (204).
6. O'chirilgan foydalanuvchining tokeni → 401.
7. SignalR (`ChatTests.ConnectAsync` naqshi): ulangan foydalanuvchi bloklanadi → `accountBlocked` hodisasi keladi; keyin `SyncChats` `HubException` beradi;
   bloklangan holda yangi ulanish rad etiladi.
8. Administrator o'zini bloklay olmaydi (mavjud qoida buzilmagan).
8b. **Rol himoyasi:** `admin@` → `superadmin@` ga `deactivate`, `activate`, `PATCH`, `DELETE`, rol berish → hammasi **403**; `admin@` → `operator@`/`teacher@`/`student@` ni bloklay oladi (200/204);
   `superadmin@` → `admin@` ni bloklay oladi. (Testda Super Admin'ni **haqiqatan** bloklab qo'ymang — faqat rad etilishini tekshiring; bloklangan bo'lsa keyingi testlar buziladi.)
9. Audit jurnalida `User` `Status` o'zgarishi bor (mavjud xatti-harakat — regressiya sifatida).
Mavjud testlar (`AuthTests`, `ScopeAuthorizationTests`) yashil qolishi shart.

**Brauzerda** (Playwright, ikki kontekst): A — admin, B — student (student sahifada). A studentni bloklaydi → B da ≤ 60 s da yoki har qanday bosishda ekran chiqadi;
tugma → `/login`; qayta kirish → ogohlantirish; A blokdan chiqaradi → B kira oladi. Ekran rasmlarini `Read` bilan ko'ring (desktop + 390px).

## 6. Qaror va xavflar
- **Nega kesh:** har so'rovga DB so'rovi qo'shilmasin. 30 s TTL + bloklash/blokdan chiqarishda **darhol** `Evict` — bitta API nusxasida bloklash bir zumda kuchga kiradi.
  Bir nechta API nusxasida (S09.07 Redis'dan keyin) TTL kechikishi 30 s gacha; o'shanda eviction Redis pub/sub bilan tarqatiladi.
- **Xabar oshkor qilish tartibi:** "bloklangan" faqat **to'g'ri parol** kiritilgandan keyin aytiladi — aks holda begona odam email bo'yicha hisob bor-yo'qligini bilib oladi.
- Middleware `/api/auth/*` ni o'tkazib yuboradi (logout ishlashi kerak); `login` va `refresh` o'z ichida holatni tekshiradi.
- `Suspended` ham bloklangan hisoblanadi (hozir hech kim qo'ymaydi, lekin enum'da bor).
- Token localStorage'da qoladi — ekrandagi tugma tozalaydi; sahifani qayta yuklasangiz birinchi so'rov yana 403 beradi va ekran qaytadi.
- `ChatHub.Subscriptions` statik lug'at — bitta API nusxasi uchun; nusxalar ko'paysa S09.07.
