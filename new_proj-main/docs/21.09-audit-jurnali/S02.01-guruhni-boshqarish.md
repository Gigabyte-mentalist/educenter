## 1. Maqsad
Guruh yaratilgandan keyin hech narsa qilib bo'lmaydi: nomni/sig'imni o'zgartirish, holatni yuritish, o'qituvchini olib tashlash, o'chirish yo'q.
`Group.Activate()` faqat seeder'da chaqiriladi — **API orqali yaratilgan har bir guruh abadiy `Forming` da qoladi**; `Completed`/`Cancelled` ga o'tish yo'li umuman yo'q.

## 2. Hozirgi holat (kodda tekshirilgan)
- `Api/Academic/GroupsController.cs`: `GET` (ro'yxat), `POST` (yaratish), `POST {id}/staff` (o'qituvchi biriktirish), `GET {id}/overview`, `GET {id}/students`. `PATCH`/`DELETE` **yo'q**.
- `Modules.Academic/Domain/Group.cs`: `GroupStatus { Forming, Active, Completed, Cancelled }`; metodlar: `AssignStaff` (takror bo'lsa `InvalidOperationException`; ikkinchi `MainTeacher` ham), `Activate()`. `RemoveStaff`, `Complete`, `Cancel`, `Update` yo'q.
- **`groups.delete` ruxsati `PermissionSeedData` da bor, lekin hech qaysi endpoint uni ishlatmaydi** (`groups.edit` — `POST staff` da ishlatiladi). Grantlarini `PermissionSeedData` dan tekshiring.
- `Lesson.TeacherId` — to'g'ridan-to'g'ri o'qituvchi (guruh xodimlari jadvalidan mustaqil): guruhdan o'qituvchini olib tashlasangiz, uning kelajakdagi darslari baribir uning nomida qoladi.
- Guruh chati (`ChatRoom.ForGroup`) — `ChatAccess` faqat **faol** enrollment'ga ruxsat beradi, shuning uchun guruh yopilganda enrollmentlar `Completed` bo'lsa chatga kirish o'zi yo'qoladi.
- Guruhga bog'langan jadvallar (o'chirishni to'sadi): `enrollments`, `lessons`, `exams` (`Exam.GroupId`), `invoices` (`Invoice.GroupId`), `support_cases`, `trial_lessons`, `chat_rooms` (`GroupId`).

## 3. Nima qilinadi

### 3.1. Domen (migratsiya kerak emas)
`Group`: `Update(string name, int capacity)`, `Complete()`, `Cancel()`, `RemoveStaff(Guid userId)` (topilmasa `InvalidOperationException`). Holat o'tishlari: `Forming → Active → Completed`, `Forming|Active → Cancelled`; teskari o'tish taqiqlangan
(`Completed`/`Cancelled` dan qaytish yo'q). `Activate()` faqat `Forming` dan.

### 3.2. Backend — `GroupsController`
| Endpoint | Ruxsat | Nima qiladi |
|---|---|---|
| `PATCH /api/groups/{id}` | `groups.edit` | `{ name?, capacity? }`. Sig'im joriy faol studentlar sonidan past bo'lmasin → 409 (xabarda son). Nom bo'sh/200 dan uzun → 400. Yopiq guruhni tahrirlab bo'lmaydi → 409 |
| `POST /api/groups/{id}/status` | `groups.edit` | `{ status }` — yuqoridagi o'tishlar; noto'g'ri o'tish → 409. `Completed` → faol/muzlatilgan enrollmentlar `Completed` (S01.03 `End`), studentlar holati `StudentStatusRules.Recompute` dan; timeline'ga `GRADUATED` **yozilmaydi** (guruh yopilishi ≠ shaxsni bitirish — u alohida `graduate` amali). `Cancelled` → enrollmentlar `Dropped` (sabab: "guruh bekor qilindi") |
| `DELETE /api/groups/{id}/staff/{userId}` | `groups.edit` | o'qituvchini olib tashlaydi. **Oxirgi `MainTeacher`** → 409. Shu o'qituvchining shu guruhdagi **kelajakdagi darslari** bo'lsa → 409 ("avval darslarni boshqa o'qituvchiga o'tkazing" — `replace-teacher` mavjud) |
| `DELETE /api/groups/{id}` | `groups.delete` | faqat **bo'sh** guruh: 2-bo'limdagi jadvallarning hech birida qator yo'q. Aks holda **409 + `blockers` ro'yxati** va `canCancel: true` (`UsersController.Delete` dagi naqsh). `GroupStaff` va bo'sh `ChatRoom` (xabarsiz) o'chiriladi |
- Bildirishnoma: guruh yopilganda/bekor bo'lganda studentlar + o'qituvchilarga (yangi tur `NotificationType.GroupClosed`); nom/sig'im o'zgarishiga yuborilmaydi.
- Hammasi `scope` bilan: `GroupAccess.CanAccessGroupAsync` yoki `AllowedBranchIds` (filial ichidagi guruh); tashkilot tekshiruvi.
- Audit: `Group` `AuditedTypes` da **yo'q** — qo'shing (yopish/o'chirish auditda bo'lishi kerak).

### 3.3. Frontend
- `lib/api/academic.ts`: `updateGroup`, `setGroupStatus`, `removeGroupStaff`, `deleteGroup`.
- `groups/[id]/page.tsx` sarlavhasi: **"Tahrirlash"** (nom, sig'im), **holat menyusi** ("Faollashtirish", "Yopish", "Bekor qilish" — `ConfirmDialog`, oqibati yozilgan: "N student guruhdan chiqadi"), xodim qatorida ✕.
- `groups/page.tsx` kartasida "O'chirish" faqat `can("groups.delete")` va guruh bo'sh bo'lsa; 409 dagi `blockers` ro'yxatini ko'rsating va "Bekor qilish" taklif qiling.
- Holat yorlig'i (`Forming/Active/Completed/Cancelled`) o'zbekcha `Badge` bilan.

## 4. Testlar — `GroupManagementTests.cs` (~10)
1. Tahrirlash; sig'im joriy sondan past → 409. 2. `Forming → Active → Completed`; teskari → 409; `Cancelled` dan qaytish → 409.
3. `Completed`: enrollmentlar `Completed`, chat endi ko'rinmaydi (student `GET /api/chats` da guruh chati yo'q). 4. `Cancelled` → enrollmentlar `Dropped`.
5. Xodim olib tashlash: oxirgi asosiy o'qituvchi → 409; kelajak darsi bor → 409; yordamchi → 204.
6. O'chirish: bo'sh guruh → 204; enrollmentli → 409 + `blockers`; darsli → 409.
7. Teacher → 403 (barchasida); administrator boshqa filial guruhi → 403; operator → 403 (`groups.edit` unda yo'q).
8. Audit jurnalida `Group` o'zgarishi.
