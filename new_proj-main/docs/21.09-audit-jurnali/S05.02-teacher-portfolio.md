## 1. Talab
"Teacher 360° ga o'qituvchining shaxsiy portfoliosi qo'shilsin: masalan **IELTS nechi**, **sertifikatlar** va shunga o'xshash — o'qituvchini o'zining qandaydur portfoliosi."
TZ §6 da portfolio yo'q (Teacher list: ixtisoslik bor, lekin kodda maydon yo'q) — bu **yangi imkoniyat**.

## 2. Hozirgi holat (kodda tekshirilgan)
- O'qituvchi = `User` (rol `TEACHER`/`SUPPORT_TEACHER`); alohida `Teacher` entity **yo'q**. `TeachersController.TeacherUsers()` shu ikki rolni tanlaydi.
- Ixtisoslik, bio, sertifikat, tajriba — hech qayerda saqlanmaydi. Foto ham yo'q (S04.04 dan keyin bor).
- Teacher sahifasiga kirish qoidasi (`TeachersController.GetById`): o'zi **yoki** keng scope (SA `AllOrganization`, AD `MyBranches` va filial ustma-ust tushishi). Hamkasb boshqasining sahifasini ochmaydi. **Shu qoida portfolio uchun ham asos.**
- Fayl yuklash naqshi: `Api/Students/StudentDocumentFileStorage.cs` (+ `StudentDocumentsController`). Ruxsat/scope naqshi: `_naqshlar.md`.

## 3. Dizayn

### 3.1. Ma'lumotlar modeli (yangi migratsiya **`AddTeacherPortfolio`**, 3 jadval)
**`TeacherProfile`** (`TenantEntity`; `UserId` unique) — "Haqida":
`Bio` (≤2000), `Specialization` (≤200, masalan "IELTS Writing"), `YearsOfExperience` (`int?`, 0–60), `Education` (≤500), `Languages` (≤200), `TeachingSince` (`DateOnly?`).

**`TeacherCredential`** (`TenantEntity`; `UserId`) — IELTS, sertifikat, diplom, kurs, mukofot — **bitta umumiy jadval**:
| Maydon | Izoh |
|---|---|
| `Type` | enum `ExamScore` (IELTS, TOEFL, CEFR…), `Certificate` (CELTA, TESOL…), `Degree`, `Course`, `Award`, `Other` |
| `Title` (≤200) | "IELTS Academic", "CELTA" |
| `Issuer` (≤200) | "British Council" |
| `Score` (≤50) | "8.0", "C1", "Pass A" — matn (IELTS 8.0 ham, CEFR C1 ham sig'adi) |
| `IssuedOn`, `ExpiresOn` | `DateOnly?` — muddati tugagan sertifikat "Muddati tugagan" belgisi bilan |
| `Reference` (≤500) | tekshirish havolasi yoki raqami (TRF/sertifikat raqami) |
| fayl | `StorageKey`, `FileName`, `FileContentType`, `FileSize` — **ixtiyoriy** skan/PDF |
| `IsVerified`, `VerifiedBy`, `VerifiedAt` | administrator hujjatni ko'rib tasdiqlaydi |
IELTS bo'lim ballari (Listening/Reading/…) alohida ustun **emas** — `Title = "IELTS Academic"`, `Score = "8.0 (L 8.5, R 8.0, W 7.5, S 8.0)"` matn sifatida (soddalik; kerak bo'lsa keyin ajratiladi).

**`TeacherExperience`** (`TenantEntity`; `UserId`) — ish tajribasi: `Employer` (≤200), `Position` (≤200), `FromYear`, `ToYear` (`int?` — hozirgacha bo'lsa bo'sh), `Description` (≤1000).

Cheklovlar: bitta o'qituvchiga ≤ 50 credential, ≤ 30 tajriba yozuvi. Auditga: `TeacherCredential` va `TeacherProfile` `AuditedTypes` ga (tasdiqlash — ishonch hodisasi).

### 3.2. Qoidalar
- **Tasdiqlash:** o'qituvchi qo'shgan credential `IsVerified = false` ("Tasdiqlanmagan"). Administrator (`teacher.portfolio.verify`) hujjatni (fayl yoki `Reference`) ko'rib "Tasdiqlash" bosadi → `IsVerified = true`, `VerifiedBy/At`.
- **Tasdiqlangandan keyin `Title`, `Issuer`, `Score`, `IssuedOn`, `ExpiresOn`, fayl o'zgartirilsa — tasdiq avtomatik bekor bo'ladi** ("tasdiqla, keyin almashtir" holati yopiladi). Faqat izoh/tartib o'zgarishi tasdiqni saqlaydi.
- Administrator o'zi qo'shgan credential darhol tasdiqlangan bo'lishi mumkin (`verified: true` bayrog'i, faqat `teacher.portfolio.verify` egasi uchun).
- **Ko'rinish:** xodim (SA/AD) — hammasini + fayllarni; o'qituvchi — o'zinikini; **student/ota-ona (ixtiyoriy 3.5)** — faqat **tasdiqlangan** yozuvlar, fayl yuklab olishsiz, `Reference` siz.
- Sarlavha "chip"lari: eng yuqori 3 ta **tasdiqlangan** `ExamScore` (yangi sanadan) — "IELTS 8.0 ✓ · CELTA ✓".

### 3.3. Ruxsatlar (`PermissionSeedData` + `docs/01` matritsasi)
| Kod | Kimda |
|---|---|
| `teacher.portfolio.view` | SA `AllOrganization`, AD `MyBranches`, Teacher `Self`, SupportTeacher `Self` |
| `teacher.portfolio.edit` | SA `AllOrganization`, AD `MyBranches` (filial o'qituvchilari uchun), Teacher `Self`, SupportTeacher `Self` |
| `teacher.portfolio.verify` | SA `AllOrganization`, AD `MyBranches` |
Scope tekshiruvi kodda: `Self` → `id == scope.UserId`; `MyBranches` → `db.UserBranches` ustma-ust tushishi (`TeachersController.GetById` dagidek); rolga sezgir himoya (S01.04): filial administratori faqat `TEACHER`/`SUPPORT_TEACHER` portfoliosini tahrirlaydi.

### 3.4. Backend — `Api/Users/TeacherPortfolioController.cs` (`[Route("api/teachers/{id:guid}")]`)
| Endpoint | Ruxsat | Izoh |
|---|---|---|
| `GET portfolio` | `.view` | `{ profile, credentials[], experience[], headline[] }` (fayl ma'lumoti: nom/hajm, **kalit emas**) |
| `PUT profile` | `.edit` | upsert `TeacherProfile` |
| `POST credentials` · `PATCH credentials/{cid}` · `DELETE credentials/{cid}` | `.edit` | 3.2 qoidalari; tasdiq bekor bo'lishi javobda (`verificationReset: true`) |
| `POST credentials/{cid}/file` · `GET credentials/{cid}/file` · `DELETE …/file` | `.edit` / `.view` | multipart, **10 MB**, pdf/png/jpg/webp (`StudentDocumentFileStorage` naqshi: yangi `TeacherCredentialFileStorage`, `App_Data/teacher-credentials`); `GET` bearer bilan, faqat xodim + egasi |
| `POST credentials/{cid}/verify` · `…/unverify` | `.verify` | tasdiqlash/bekor qilish; teacherga bildirishnoma (`NotificationType.CredentialVerified`) |
| `POST/PATCH/DELETE experience[/{eid}]` | `.edit` | oddiy CRUD |
- O'qituvchi yangi credential qo'shganda filial administratorlariga bildirishnoma (`NotificationType.CredentialSubmitted`, `recipients.BranchAdministratorsAsync`) — "tasdiqlash uchun".
- `TeacherListDto` ga `headline` (chip'lar) qo'shing yoki `/api/teachers` ro'yxati uchun alohida yengil so'rov (N+1 bo'lmasin: bitta so'rov bilan hamma o'qituvchilar chiplarini oling).
- Tekshiruv: maydon uzunliklari, `ExpiresOn >= IssuedOn`, `Score` bo'sh emas (ExamScore uchun).

### 3.5. (Ixtiyoriy — alohida commit) Student/ota-onaga ko'rsatish
"Mening o'qituvchim" — student `Self` va ota-ona `MyChildren` o'z guruhlarini o'qitadigan o'qituvchining **tasdiqlangan** portfoliosini o'qiydi (fayl va `Reference` siz).
Yangi ruxsat `teacher.portfolio.view.public` (Student `Self`, Parent `MyChildren`); scope: o'qituvchi shu student(lar)ning **faol** guruhida `GroupStaff` bo'lsin. Guruh sahifasidagi o'qituvchi ismidan havola. **Bu qismni boshlashdan oldin foydalanuvchidan tasdiq oling** (shaxsiy ma'lumot ko'rinishi — maxfiylik qarori).

### 3.6. Frontend
- `lib/api/teachers.ts`: portfolio funksiyalari va tiplar.
- `teachers/[id]/page.tsx` ga **"Portfolio"** tabi → `components/teachers/TeacherPortfolioTab.tsx`: bloklar — **Haqida** (bio, ixtisoslik, tajriba yili, ta'lim, tillar), **Malaka va sertifikatlar** (kartalar: nom, beruvchi, ball, sana, "Tasdiqlangan ✓ / Tasdiqlanmagan / Muddati tugagan" `Badge`, fayl tugmasi), **Ish tajribasi** (vaqt chizig'i).
  Tahrirlash `Drawer`lar (`can("teacher.portfolio.edit")` va scope: o'z sahifasi yoki administrator); "Tasdiqlash" tugmasi `can("teacher.portfolio.verify")`, tasdiqlashdan oldin faylni ochish imkoni; tasdiq bekor bo'lganda ogohlantirish ("Tahrirlash tasdiqni bekor qiladi").
- Sarlavhada (`teachers/[id]/page.tsx` `PageHeader`) chip'lar; `teachers/page.tsx` ro'yxatida ixtisoslik + 1-2 chip.
- Birinchi kirishda o'qituvchining o'z dashboardida "Portfolioingizni to'ldiring" eslatmasi (ixtiyoriy, kichik karta).

## 4. Testlar — `TeacherPortfolioTests.cs` (~14)
1. Teacher o'z profilini/credential/tajribasini CRUD qiladi. 2. Boshqa teacher (hamkasb) → 403 (GET ham, POST ham). 3. Administrator (o'z filiali) ko'radi/tahrirlaydi; boshqa filial → 403; operator → 403.
4. Tasdiqlash faqat SA/AD; teacher o'z credentialini tasdiqlay olmaydi (403). 5. **Tasdiqlangan credential `Score` ni o'zgartirsa → `IsVerified=false`**; izohni o'zgartirsa saqlanadi.
6. Fayl: yuklash/olish/almashtirish/o'chirish; 10 MB dan katta → 400; `.exe`/`.svg` → 400; fayl faqat xodim va egasiga (student → 403). 7. Bildirishnoma: qo'shganda administratorga, tasdiqlanganda teacherga.
8. Sarlavha chip'lari: faqat tasdiqlangan `ExamScore`. 9. Limitlar (51-credential → 409/400). 10. Audit jurnalida tasdiqlash. 11. (3.5 bo'lsa) student faqat o'z o'qituvchisining tasdiqlanganlarini ko'radi, faylsiz.
