## 1. Maqsad
TZ §11: "Super Admin marketing conversionni **source** bo'yicha ko'ra oladi." `Lead.Source` bazada bor va doskada filtr sifatida ishlatiladi, lekin **manba → trial → student → to'lov** voronkasi hisoboti yo'q.

## 2. Hozirgi holat (kodda tekshirilgan)
- `Lead.Source` (matn: Instagram, Telegram, Website, Referral, Outdoor Ads, Call, Walk-in…), `LeadStatus` (`Lead, Contacted, TrialBooked, TrialAttended, TrialMissed, NotInterested, Lost, Converted`), `Lead.ConvertedStudentId`, `TrialLesson`, `Payment` (`StudentId`, `IsVoided`).
- S05.03 dagi `Api/Crm/LeadFunnelQueries.cs` (Branch CRM bloki) — voronka so'rovlari **shu yerda**; bu qadam uni umumiy endpointga chiqaradi va manba bo'yicha bo'ladi.
- Frontend: `/leads` doskasi (`app/(admin)/leads/page.tsx`).

## 3. Nima qilinadi
- **Backend:** `GET /api/leads/funnel?from=&to=&branchId=&source=` (`leads.view`, scope: `AllowedBranchIds`) →
  ```
  FunnelDto(Stages[ { Key, Label, Count, ConversionFromPrevious } ], BySource[ { Source, Stages[...] } ])
  Bosqichlar: Lidlar → Bog'lanilgan → Trial band → Trial keldi → Student bo'ldi → To'lov qildi
  ```
  "Bog'lanilgan" = kamida bitta `CrmCall` yoki status `Contacted+`; "Trial band/keldi" = `TrialLesson` (`Scheduled/Attended`); "Student bo'ldi" = `Converted`; "To'lov qildi" = konvertatsiya qilingan studentda `Payment` (`!IsVoided`) bor.
  Davr: lid `CreatedAt` bo'yicha (kohorta), `from/to ≤ 366`; har bosqich oldingi bosqichga nisbatan % va lid soniga nisbatan %. Manba nomlari normallashtiriladi (`Trim`, katta-kichik harf); bo'sh manba "Ko'rsatilmagan".
- **Frontend:** `/leads` sahifasiga **"Voronka"** tabi (doska/voronka almashtirgich): gorizontal voronka diagrammasi (`recharts` — S05.03 da qo'shilgan) va manbalar jadvali (manba · lid · trial · student · to'lov · konversiya %), davr va filial filtri.
  Mobilda jadval gorizontal skroll (sahifa emas). Branch dashboard CRM bloki (S05.03) o'sha endpoint natijasidan foydalansin — ikki joyda ikki xil formula bo'lmasin.
