## 3. Nima qilinadi

### 3.1. Domen (migratsiya **`AddNotificationDelivery`**)
- `NotificationChannel` ga `Email`, `Sms` (enum matn — migratsiya faqat yangi jadval uchun).
- Yangi `NotificationDelivery(Id, OrganizationId, NotificationId, Channel, Status {Pending, Sent, Failed, Skipped}, Attempts, Error?, SentAt?)` — har kanal uchun alohida qator (qayta urinish va hisobot uchun; `Notification` ga ustun qo'shmang).
- `NotificationMessage` ga ixtiyoriy `ExternalBody` (Email/SMS matni): **sezgir ma'lumot to'liq yuborilmaydi** (TZ §23) — standart tashqi matn: sarlavha + "Batafsil: {link}"; summa/ism/ball faqat ilovada.

### 3.2. Yetkazish arxitekturasi
```csharp
public interface INotificationSender { NotificationChannel Channel { get; } Task<SendResult> SendAsync(NotificationTarget target, NotificationEnvelope message, CancellationToken ct); }
```
- `SmtpEmailSender` — **MailKit** (NuGet; Docker'da `restore`), sozlama `Notifications:Email` (`Host, Port, UseStartTls, User, Password, From`), o'chirilgan bo'lsa `NoopSender` (Skipped).
- `SmsSender` — O'zbekiston provayderi (Eskiz.uz yoki Play Mobile) HTTP API: `Notifications:Sms` (`Provider, BaseUrl, ApiKey/Login/Password, Sender`); `HttpClient` (`AddHttpClient`), timeout, xato matni `Error` ga (200 belgi).
  **Kunlik limit** `Notifications:Sms:DailyLimit` (standart 200) — oshsa `Skipped` ("limit"); SMS pulli, **standart o'chiq**.
- `TelegramSender` — faqat interfeys/`NotImplemented` o'rniga hech narsa **yozmang** (bloklangan).
- **`INotificationDeliveryQueue`** (`HangfireDeliveryQueue` / `InlineDeliveryQueue` — `AiJobQueue` naqshi) va `NotificationDeliveryJob`: `NotificationDispatcher` inbox qatorini yozgach, har bir **yoqilgan** kanal uchun `NotificationDelivery(Pending)` yozadi va **saqlashdan keyin** queue'ga qo'yadi (SMTP/SMS so'rovi HTTP so'rovni kutdirmasin). Xato bo'lsa 3 marta qayta urinish (eksponensial), keyin `Failed`; **inbox qatori har doim qoladi**.
- Kanal standartlari (kodda `ChannelDefaults[(type, channel)]`): **Email** — `PAYMENT_DUE`, `PAYMENT_OVERDUE`, `ABSENCE_STREAK`, `EXAM_RESULT` uchun yoqiq, qolganiga o'chiq; **SMS** — hammasi o'chiq. Foydalanuvchi sozlamasi standartni bosib o'tadi ("qator bor" → uning qiymati). Tashkilot darajasidagi standartlar S07.01 da.
- Havola uchun mutlaq manzil: `App:PublicUrl` (config) + `Notification.Link`.

### 3.3. Sozlamalar API va UI
- `GET /api/notifications/preferences` javobiga `channels: { inApp, email, sms }`; `PUT preferences/{type}` ga `{ inApp?, email?, sms? }` (orqaga moslik: `inAppEnabled` ham qabul qilinsin yoki frontend bilan birga o'zgartiring). Email/SMS faqat foydalanuvchida manzil/telefon bo'lsa taklif qilinadi.
- `settings/notifications/page.tsx`: jadvalga **Email** va **SMS** ustunlari (kanallar ro'yxatidan qurilgan — o'zgarish kichik); "SMS pulli bo'lishi mumkin" izohi; telefon/email yo'q bo'lsa ustun o'chirilgan.

## 4. Testlar — `NotificationsTests.cs` ga +~7 (test `factory` da soxta `INotificationSender`lar: `ConfigureTestServices`)
1. Email yoqilgan tur → soxta sender chaqiriladi, `NotificationDelivery.Sent`. 2. O'chirilgan kanalga yuborilmaydi. 3. **Sender xato bersa inbox qatori baribir bor**, delivery `Failed` (3 urinishdan keyin).
4. Dedupe: bir xil `DedupeKey` ikki marta → bitta yetkazish. 5. SMS kunlik limit → `Skipped`. 6. Tashqi matnda summa/ism yo'q, faqat sarlavha + havola. 7. Sozlamalar: kanal yoqish/o'chirish saqlanadi; rolga mos bo'lmagan tur → 400 (mavjud).
Mavjud bildirishnoma testlari yashil (inbox xatti-harakati o'zgarmaydi).
