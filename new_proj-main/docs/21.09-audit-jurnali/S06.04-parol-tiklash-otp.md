## 1. Maqsad
Parolni unutgan foydalanuvchi administratorga bog'lanmasdan o'zi tiklay olsin: email (yoki telefon) → 6 raqamli kod → yangi parol.

## 2. Hozirgi holat
`AuthController`: `login/refresh/logout` (+ S01.05: `change-password`). Parol tiklash yo'q. Email/SMS yetkazish S06.03 dan keyin bor. `User.Email` unique; `User.Phone` **unique emas**.
`LoginBruteForce` rate-limit siyosati mavjud (`Program.cs`, IP bo'yicha daqiqada 10).

## 3. Nima qilinadi
- **Domen:** `PasswordResetToken(Id, UserId, CodeHash, ExpiresAt, UsedAt?, Attempts, CreatedAt)`; migratsiya **`AddPasswordResetTokens`**. Kod **xeshlanadi** (parol kabi yoki SHA-256 + tuz), ochiq saqlanmaydi.
- **Endpointlar (`[AllowAnonymous]`, `LoginBruteForce` bilan):**
  | Endpoint | Nima qiladi |
  |---|---|
  | `POST /api/auth/forgot-password` `{ identifier }` | **Har doim 204** (foydalanuvchi bor-yo'qligini oshkor qilmaydi). Email bo'yicha topilsa (yoki telefon **bitta** foydalanuvchiga mos kelsa) 6 raqamli kod (`RandomNumberGenerator`) yaratadi, 15 daqiqa, Email/SMS yuboradi (S06.03: `ExternalBody` — "Tasdiqlash kodi: 123456"; **bu yagona joy** — kodning o'zi tashqariga ketadi, shuning uchun in-app inbox qatori yozilmaydi). Bloklangan foydalanuvchiga **yubormaydi** (jim). Bir foydalanuvchiga soatiga ≤ 3 ta so'rov (yangi kod eskisini bekor qiladi) |
  | `POST /api/auth/reset-password` `{ identifier, code, newPassword }` | kod to'g'ri, muddat o'tmagan, `Attempts < 5` → `PasswordPolicy`, yangi xesh, `MustChangePassword = false`, **barcha refresh tokenlar bekor**, token `UsedAt`, kesh yangilanadi. Noto'g'ri kod `Attempts++`, 5 ta xato → token bekor. Xato javob **bir xil** ("Kod noto'g'ri yoki muddati o'tgan") |
- Audit: parol tiklash hodisasi (`User` o'zgarishi) avtomatik yoziladi; kod hech qayerga loglanmasin.
- **Frontend:** `app/(auth)/forgot-password/page.tsx` — ikki qadam (email/telefon → kod + yangi parol), loginda "Parolni unutdingizmi?" havolasi; muvaffaqiyatda `/login` ga. Bloklangan foydalanuvchi "kod keldi" deb o'ylab kutmasin — umumiy matn: "Agar hisob mavjud bo'lsa, kod yuborildi."

## 4. Testlar — `PasswordResetTests.cs` (~7)
1. To'g'ri oqim: kod soxta sender'dan olinadi → yangi parol → login ishlaydi, eski token/refresh ishlamaydi. 2. Mavjud bo'lmagan email → 204 (va hech narsa yuborilmagan). 3. Noto'g'ri kod 5 marta → token bekor, to'g'ri kod ham endi ishlamaydi.
4. Muddati o'tgan kod → xato. 5. Ikkinchi so'rov birinchi kodni bekor qiladi. 6. Bloklangan foydalanuvchiga kod yuborilmaydi (204). 7. Soatiga 3 dan ortiq so'rov → jim throttling (204, yuborilmaydi).
