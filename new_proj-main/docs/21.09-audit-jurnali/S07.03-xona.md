## 1. Maqsad
`Lesson.RoomName` — oddiy matn; xona sig'imi, jihozi, kunlik bandligi yo'q. `GET /api/schedule/rooms` faqat ishlatilgan nomlarni yig'adi. TZ §18 "Room Management": xona bandligi, sig'im.

## 2. Hozirgi holat (kodda tekshirilgan)

- Demo seeder xona nomlarini matn sifatida beradi (`DemoDataSeeder`: A101, B201, S102…).

## 3. Nima qilinadi
- **Domen** (`BranchScopedEntity`): `Room(OrganizationId, BranchId, Name (≤100), Capacity (int?), Equipment (≤500), IsActive)`; `(BranchId, Name)` unique. `Lesson` ga `RoomId` (`Guid?`) — **`RoomName` qoladi** (tarixiy yozuvlar va orqaga moslik). Migratsiya **`AddRooms`**: jadval + `lessons.RoomId` + **ma'lumot ko'chirish** (`INSERT INTO rooms SELECT DISTINCT branch_id, room_name …`, so'ng `UPDATE lessons SET room_id = …` nom bo'yicha) — migratsiya ichida raw SQL.
- **Konflikt:** `RoomId` bo'yicha (nom bo'yicha emas); `RoomId == null` eski darslar — nom bo'yicha (o'tish davri). Xona `IsActive = false` bo'lsa yangi darsga tanlanmaydi.
- **Endpointlar:** `GET /api/rooms?branchId=` (`schedule.view`, `IsActive` filtri), `POST/PATCH/DELETE /api/rooms` (yangi `rooms.manage`: SA `AllOrganization`, AD `MyBranches`; **darsi bor xonani o'chirib bo'lmaydi** — 409, "nofaol qiling"), `GET /api/rooms/{id}/availability?date=` (kun bo'yicha band oraliqlar: dars, guruh, o'qituvchi).
  `GET /api/schedule/rooms` **saqlansin** (eski frontend) yoki `GET /api/rooms` ga o'tkazilib olib tashlansin — frontend'ni birga o'zgartiring.
- **Yumshoq tekshiruv:** dars yaratish/tahrirlashda xona sig'imi guruh sig'imidan kichik bo'lsa **ogohlantirish** (`warnings[]` javobda; xato emas).
- **`LessonCandidate`/`LessonDto`/`CreateLesson`/`PATCH lesson`**: `roomId` qabul qiladi; `roomName` javobda xona nomi bo'lib qoladi (orqaga moslik).
- **Frontend:** `/rooms` sahifasi yoki filial sahifasida "Xonalar" bo'limi (jadval: nom, sig'im, jihoz, faol; drawer); `schedule/page.tsx` dagi `<datalist>` o'rniga `<Select>` (xonalar ro'yxati + sig'im); dars kartasida xona nomi. Kun modalida "Xona bandligi" (ixtiyoriy).
