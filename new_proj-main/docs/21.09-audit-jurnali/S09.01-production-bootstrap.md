## 2. Nima qilinadi

### 2.1. Rol/ruxsat sinxroni — **hamma muhitda** (`Infrastructure/Seed/RolePermissionSync.cs`)
`DbSeeder` dagi `SeedRolesAsync` (rollar), `SeedPermissionsAsync`, `SeedRolePermissionsAsync` mantiqini **demo ma'lumotdan ajratib** alohida sinf qiling (`RolePermissionSync.SyncAsync(db)`): idempotent — yo'q rol/ruxsat/grant qo'shiladi, scope farq qilsa yangilanadi (mavjud xatti-harakat).
- `DbSeeder.SeedAsync` uni chaqiradi (o'zgarish yo'q); **`Program.cs` esa uni har muhitda** (Development, Staging, **Production**) startda chaqiradi — **demo foydalanuvchilar/ma'lumot faqat Development'da**.
- S07.02 (ruxsat muharriri) bo'lsa: sinxron faqat kod defoltlarini yozadi, override jadvaliga tegmaydi (u alohida qatlam).
- Ko'p nusxada bir vaqtda ishga tushishda poyga bo'lmasin: `pg_advisory_lock` (bitta kalit) bilan o'rang.

### 2.2. Migratsiya
- `Database:MigrateOnStartup` (bool): **Development va testlarda `true`** (hozirgi xatti-harakat: skript orqali), **Production'da standart `false`** — deploy skripti/bir martalik konteyner bajaradi (`dotnet EduCenter.Api.dll migrate` buyrug'i — 2.3) yoki `true` qilib `pg_advisory_lock` ostida `MigrateAsync`. Qaysi biri — foydalanuvchi bilan kelishing; tavsiya: **alohida `migrate` buyrug'i** (xavfsizroq: ilova ishga tushmasdan oldin bajariladi).
- Kutilayotgan migratsiya bo'lsa production ilova **aniq xato bilan** ishga tushmasligi (yoki `/healthz` "not ready" berishi) — Developer paneli allaqachon qo'llanmagan migratsiyalarni ko'rsatadi (`system/deployment`).

### 2.3. Buyruqlar qatori (`Program.cs` boshida, `builder` dan oldin) — `Api/Bootstrap/BootstrapCommands.cs`
`dotnet EduCenter.Api.dll <buyruq>`: 
| Buyruq | Nima qiladi |
|---|---|
| `migrate` | kutilayotgan migratsiyalarni qo'llaydi va chiqadi (kod 0/1) |
| `bootstrap --org "Markaz nomi" --slug markaz --email admin@markaz.uz` | **faqat baza bo'sh bo'lsa** (tashkilot yo'q): tashkilotni, birinchi filialni (`--branch`, `--timezone`) va **Super Admin**ni yaratadi; parolni **stdin/`BOOTSTRAP_PASSWORD` env** dan oladi (argument sifatida emas — shell tarixiga tushmasin), `PasswordPolicy`; `MustChangePassword = true` (S01.05 bor bo'lsa). Tashkilot allaqachon bor → xato (qayta ishga tushirib bo'lmaydi) |
| (buyruq yo'q) | odatdagi veb-server |
Buyruq bo'lmasa `WebApplication` odatdagidek ishlaydi (mavjud testlar `Program` ga tegmaydi — `WebApplicationFactory` uchun `public partial class Program` saqlansin).

### 2.4. Konfiguratsiya tekshiruvi (`Api/Bootstrap/StartupValidation.cs`, faqat **Production**da fail-fast, aniq xabar bilan)
`Jwt:SigningKey` ≥ 32 bayt **va dev kaliti emas**; `ConnectionStrings:Postgres` berilgan; `Ai:AllowFakeProvider = false`; `Cors:AllowedOrigins` bo'sh emas (S09.03 dan keyin); `Files:Scanner:Required` (S08.03 dan keyin — skaner sozlanmagan bo'lsa ogohlantirish). `AllowedHosts` `*` bo'lsa **ogohlantirish** logi. Development'da tekshiruv o'chiq. `appsettings.json` dagi dev kalitini **olib tashlamang** (dev ishlashi uchun kerak) — production'da env (`Jwt__SigningKey`) bilan almashtiriladi.

### 2.5. Sog'liq tekshiruvi
`GET /healthz` (**anonim**, faqat holat kodi: 200/503 — versiya, hisoblar, xato matni **yo'q**): DB'ga `SELECT 1` va "kutilayotgan migratsiya yo'q". `GET /livez` — jarayon tirik. (`/api/system/health` Developer paneli uchun qoladi.)

## 3. Testlar — `BootstrapTests.cs` (~7; ba'zilari unit)
1. `RolePermissionSync` bo'sh bazada 8 rol + hamma grantni yaratadi; ikkinchi marta hech narsa o'zgarmaydi; scope o'zgarganda yangilaydi. 2. `bootstrap` bo'sh bazada tashkilot+filial+Super Admin yaratadi; ikkinchi chaqiruv xato.
3. Bootstrap'dagi Super Admin login qila oladi va `students.view` ni oladi (sinxron ishlagan). 4. `StartupValidation`: dev kaliti + Production → xato; yaxshi kalit → o'tadi (sof funksiya sifatida test qiling — butun ilovani Production'da ko'tarmasdan).
5. `/healthz` anonim 200; DB yo'q bo'lsa 503 (test: noto'g'ri connection string bilan alohida host — qiyin bo'lsa unit darajada). 6. Development seed va mavjud 173+ test o'zgarishsiz yashil.
