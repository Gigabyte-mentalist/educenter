## 1. Maqsad
Hozir tenant izolyatsiyasi **qo'lda**: har bir so'rov `OrganizationId == scope.OrganizationId` ni o'zi yozadi. Bitta unutilgan `Where` — tashkilotlararo ma'lumot sizishi. Bitta tashkilot bor paytda ko'rinmaydi, SaaS'da (S10.09) halokatli. **Arxitektura xavfi — keyinroq tuzatish ancha qimmat.**

## 2. Hozirgi holat (kodda tekshirilgan)
- `Infrastructure/AppDbContext.cs`: `HasQueryFilter` **yo'q**; `OnModelCreating` konfiguratsiyalarni assembly'lardan yuklaydi. `SharedKernel/BaseEntity.cs`: `TenantEntity` (`OrganizationId`), `BranchScopedEntity` (+`BranchId`).
- **Hamma entity `TenantEntity` emas:** `UserRole`, `UserBranch`, `StudentParent`, `GroupStaff`, `ChatMember`, `RefreshToken`, `RolePermission`, `UserPermission`, `Permission`, `Role` — `OrganizationId` yo'q (join/global jadval). `Organization` o'zi ham `TenantEntity` emas.
- Kim `OrganizationId` ni biladi: JWT'da `org` claim'i (`JwtTokenService`: `new("org", user.OrganizationId)`), `ResolvedScope.OrganizationId` (`PermissionResolver`). **Tokensiz kontekstlar:** `AuthController.Login/Refresh` (foydalanuvchi email bo'yicha global topiladi — `users.Email` unique **global**), Hangfire joblari (`AutomationSweepJob`, `KnowledgeIngestionJob`, `WritingEvaluationJob` — barcha tashkilotlar bo'ylab), `DbSeeder`/`DemoDataSeeder`, testlar.
- `AuditSaveChangesInterceptor` `IHttpContextAccessor` orqali `org` ni oladi — tenant-provider uchun namuna.

## 3. Nima qilinadi
- **`ITenantProvider`** (scoped): `Guid? OrganizationId`, `bool IsSystem`. Manba: `HttpContext.User` `org` claim'i; HTTP kontekst yo'q yoki token yo'q → `OrganizationId = null`. `TenantScope.System()` — Hangfire/seeder/bootstrap uchun **aniq, o'qiladigan** chetlab o'tish (`using var _ = tenant.AsSystem();`).
- **Filtr:** `AppDbContext` ga `ITenantProvider` inject qiling; `OnModelCreating` da `TenantEntity` dan meros olgan har bir entity turi uchun
  `e => tenant.IsSystem || tenant.OrganizationId == null || e.OrganizationId == tenant.OrganizationId`.
  ⚠️ EF query filter'da **DbContext instance maydoni**ga murojaat qilish kerak (`_tenant`) — `modelBuilder` da ifoda DbContext a'zosini ushlaydi; `EF.Property`/umumiy metod bilan turlar bo'yicha `HasQueryFilter` (namuna: "global filter per tenant" EF hujjati). `OrganizationId == null` (tokensiz) holatda **filtrsiz** (login/refresh ishlashi uchun) — lekin **anonim endpointlar faqat aniq kerakli jadvallarni o'qishi** kerak (Login: `users`, `roles`, `refresh_tokens`).
- **`IgnoreQueryFilters()`** faqat aniq joylarda (izoh bilan): `AuthController.Login` (email global), `Refresh`, `DbSeeder`. Mavjud qo'lda filtrlar **qoladi** (ikki qavat himoya; hech narsani olib tashlamang).
- **`TenantEntity` bo'lmagan jadvallar** filtrsiz (ular egasi orqali himoyalanadi: `user_roles` — `User` orqali). Yangi entity `TenantEntity` dan meros olsa filtr avtomatik qo'llanadi (yangi kod uchun yaxshi xavfsiz-defolt).
- **Yozishda ham:** `SaveChanges` da `TenantEntity.OrganizationId` bo'sh/boshqa tashkilotniki bo'lsa (tokenli kontekstda) **rad** (interceptor: `Added` entity `OrganizationId != tenant.OrganizationId` → `InvalidOperationException`) — noto'g'ri tashkilotga yozishni ham to'xtatadi.
- **Hangfire joblari:** har job ichida `tenant.AsSystem()` va tashkilotlar bo'ylab tsikl (`AutomationSweepJob`, `AutomationRunner`) yoki job argumentida `organizationId` bo'lsa `tenant.For(organizationId)`.
- **Unumdorlik:** filtr indekslarga ta'sir qilmaydi (allaqachon `OrganizationId` ko'p indekslarda), lekin `EXPLAIN` bilan 2–3 og'ir so'rovda tekshiring.

## 4. Testlar — `TenantIsolationTests.cs` (~10) — **eng muhim qism**
Ikkinchi tashkilot yaratiladi (test yordamchisi: yangi `Organization` + filial + foydalanuvchi + bir nechta student/guruh/to'lov/lid). Birinchi tashkilot foydalanuvchisi **20 ta asosiy endpoint** bo'ylab (`/api/students`, `/api/groups`, `/api/finance/invoices|payments|debtors`, `/api/leads`, `/api/schedule`, `/api/exams`, `/api/users`, `/api/dashboard/organization`, `/api/search`, `/api/support-cases`, `/api/audit-logs`, `/api/notifications`, `/api/chats`…) ikkinchi tashkilot ma'lumotini **hech qachon** olmasligi tekshiriladi:
- ro'yxatlar bo'sh/faqat o'ziniki; id bo'yicha `GET/PATCH/DELETE` → 404/403. 2. **Qo'lda filtr olib tashlangan** deb tasavvur qiling: bitta test `IgnoreQueryFilters` siz xom `db.Students.ToListAsync()` (tokenli kontekstda) faqat o'z tashkilotini qaytarishini tekshiradi (filtr o'zi ishlashini isbotlaydi).
- 3. Login/refresh ikkala tashkilot foydalanuvchisi uchun ishlaydi. 4. Hangfire job (`AutomationRunner`) har ikkala tashkilot uchun ishlaydi. 5. Noto'g'ri `OrganizationId` bilan yozish urinishi rad etiladi. 6. Mavjud 173+ test yashil.
