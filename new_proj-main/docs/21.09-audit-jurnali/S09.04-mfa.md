> **Sessiya boshlash:** `docs/21.09-audit-jurnali/S09.04-mfa.md ni o'qi va faqat shu qadamni bajar.`

## 1. Maqsad
Super Admin va Developer (va istagan boshqa foydalanuvchi) uchun ikki bosqichli tasdiqlash: parol + autentifikator ilovasi kodi (TOTP). Bugun faqat parol.

## 2. Hozirgi holat
- `Api/Auth/AuthController.Login` parol tekshiradi → `TokenResponse`. `JwtTokenService` access (15 daqiqa) + refresh (7 kun). `User` da MFA maydonlari yo'q. Shifrlash kalitlari infratuzilmasi (Data Protection) sozlanmagan.
- S01.04/S01.05 dan: `AccountStatusMiddleware` + `UserStatusCache` (`AccountState`) — "majburiy MFA sozlash" holati shu yerda **serverda** majburlanadi (`PASSWORD_CHANGE_REQUIRED` kabi).
- Frontend login: `app/(auth)/login/page.tsx`.

## 3. Nima qilinadi
- **Domen** (migratsiya **`AddMfa`**): `User.MfaSecretProtected` (`string?` — TOTP siri **shifrlangan**: ASP.NET `IDataProtector` (kalitlar doimiy saqlanishi kerak — `PersistKeysToDbContext`/fayl; production'da bo'sh konteynerda yo'qolmasin!)), `MfaEnabledAt`, `MfaLastUsedStep` (`long?` — bir xil kodni qayta ishlatishni oldini olish); `MfaRecoveryCode(UserId, CodeHash, UsedAt?)` (10 ta, bir martalik, xeshlangan).
- **Kutubxona:** `Otp.NET` (TOTP, SHA-1, 6 raqam, 30 s, ±1 qadam oynasi).
- **Endpointlar (`/api/auth/mfa/…`):**
  | Endpoint | Nima qiladi |
  |---|---|
  | `POST setup` (`[Authorize]`) | yangi sirni yaratadi (hali yoqilmagan), `otpauth://totp/EduCenter:{email}?secret=…&issuer=EduCenter` qaytaradi |
  | `POST enable` `{ code }` | birinchi kodni tekshiradi → yoqadi, **10 ta tiklash kodini bir marta** qaytaradi |
  | `POST disable` `{ password, code }` | parol + kod talab qiladi (majburiy rollar o'chira olmaydi — 3-band) |
  | `POST login` | parol to'g'ri va MFA yoqilgan → **`{ mfaRequired: true, mfaToken }`** (qisqa muddatli, 5 daqiqa, alohida `purpose=mfa` claim'li JWT; **API chaqirish uchun yaroqsiz**) |
  | `POST mfa/verify` `{ mfaToken, code }` yoki `{ mfaToken, recoveryCode }` | to'g'ri → to'liq token juftligi. 5 ta xato → mfaToken bekor (`LoginBruteForce` bilan) |
- **Majburiy qilish:** tashkilot sozlamasi (S07.01) "MFA majburiy rollar" (standart: `SUPER_ADMIN`, `DEVELOPER`); MFA'siz shunday foydalanuvchi kirsa `AccountState.MfaSetupRequired` → guard `403 { code: "MFA_SETUP_REQUIRED" }` (faqat `/api/auth/*` ochiq) → frontend `/settings/security` sozlash ekraniga majburan. Majburiy roldagi foydalanuvchi MFA'ni o'chira olmaydi.
- **Administrator qayta tiklashi:** foydalanuvchi telefon/kodni yo'qotsa — `POST /api/users/{id}/mfa/reset` (`users.password.reset` — S01.05 dagi yangi ruxsat; rolga sezgir himoya): MFA o'chiriladi, tokenlar bekor, keyingi kirishda qayta sozlash. Audit'da.
- **Frontend:** login'da ikkinchi qadam (6 xonali kod, "tiklash kodini ishlatish" havolasi); `settings/security/page.tsx` (S01.05 da yaratilgan) ga "Ikki bosqichli tasdiqlash": QR (**mijoz tomonida** `qrcode` kutubxonasi bilan `otpauth://` dan; siri serverdan tashqariga boshqa yo'l bilan ketmasin), yoqish, tiklash kodlarini ko'rsatish/yuklab olish (bir marta).
- **Xavfsizlik:** kod taqqoslash doimiy vaqtda; `MfaLastUsedStep` dan katta qadam bo'lishi shart (replay yo'q); tiklash kodlari xeshlangan; sir/kod logga tushmasin.

## 4. Testlar — `MfaTests.cs` (~9; TOTP'ni testda `Otp.NET` bilan hisoblang)
1. setup → enable (to'g'ri kod) → 10 tiklash kodi; noto'g'ri kod → 400. 2. MFA yoqilgan foydalanuvchi login → `mfaRequired`, `mfaToken` **API chaqirishga yaramaydi** (401/403). 3. `verify` to'g'ri kod → tokenlar. 4. **Bir xil kodni ikkinchi marta** → rad (replay).
5. Tiklash kodi bir marta ishlaydi. 6. 5 ta xato → mfaToken bekor. 7. Majburiy rol MFA'siz → `MFA_SETUP_REQUIRED` va `/api/auth/mfa/setup` ochiq; sozlagach oddiy ishlaydi. 8. Administrator `SUPER_ADMIN` MFA'sini reset qila olmaydi (403); SA operatorniki mumkin. 9. Mavjud login testlari (MFA yo'q foydalanuvchilar) o'zgarishsiz.
