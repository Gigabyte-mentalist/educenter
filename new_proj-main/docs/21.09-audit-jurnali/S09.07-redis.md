## 1. Maqsad
- **SignalR backplane yo'q** → ikkinchi API nusxasida chat buziladi (`ChatHub.Subscriptions` — statik, xotirada, bitta jarayon uchun).
- **Kesh yo'q** → dashboard hisoblari (S05.03), `/api/me/permissions`, AI limit hisoblagichlari har safar bazadan.

## 2. Hozirgi holat (kodda tekshirilgan)
- `Api/Chat/ChatHub.cs`: `Subscriptions` (`ConcurrentDictionary<string, HashSet<Guid>>`, connectionId → chat id'lar), S01.04 dan keyin `UserConnections` ham shunday statik. `Program.cs`: `AddSignalR()...AddJsonProtocol(...)` — backplane yo'q.
- `Api/Ai/AiLimits.cs`, `Api/Automation/*`, S01.04 `UserStatusCache` (`IMemoryCache`), S05.03 dashboard keshi (`IMemoryCache`) — hammasi **jarayon-ichi** xotira keshi.
- `docker-compose.yml` da Redis yo'q (boshqa loyihada `lcsystem-redis-1` ishlab turibdi — **unga tegmang**, alohida nom bilan yangi konteyner).

## 3. Nima qilinadi
- `docker-compose.yml` ga `redis` (`redis:7-alpine`, alohida nom/port). `Microsoft.AspNetCore.SignalR.StackExchangeRedis` NuGet.
- **Backplane:** `Redis:ConnectionString` bo'lsa `builder.Services.AddSignalR().AddStackExchangeRedis(connectionString, options => options.Configuration.ChannelPrefix = "educenter")`; bo'lmasa (dev, standart) hozirgi xatti-harakat (bitta nusxa). `ChatHub.Subscriptions`/`UserConnections` **statik lug'at bo'lib qoladi** — backplane faqat SignalR guruh xabarlarini nusxalar orasida tarqatadi, obuna ro'yxati har nusxada mahalliy (bu to'g'ri: har ulanish bitta nusxaga bog'lanadi).
- **Kesh:** `IDistributedCache` (`AddStackExchangeRedisCache` bo'lsa; bo'lmasa `AddDistributedMemoryCache` — interfeys bir xil, kod o'zgarmaydi). S01.04 `UserStatusCache`, S05.03 dashboard keshi, `AiLimits` hisoblagichlari **`IMemoryCache` o'rniga `IDistributedCache`** ga o'tkaziladi (JSON serialize/deserialize bilan; kalit prefiksi `org:{id}:...` — S09.02 tenant izolyatsiyasi bilan mos).
  ⚠️ **Eviction naqshi o'zgaradi:** S01.04 dagi `UserStatusCache.Evict` `IMemoryCache.Remove` edi — `IDistributedCache.RemoveAsync` bilan almashtiring, xatti-harakat bir xil qoladi (bloklashda kesh darhol tozalanadi, endi bir nechta API nusxasida ham).
- Sozlama yo'q bo'lsa (Redis ulanmagan) tizim **ishlashda davom etadi** (xotira kesh/bitta nusxa) — Redis ixtiyoriy bog'liqlik, majburiy emas.

## 4. Testlar
- `SignalR backplane`: qo'lda ikkinchi API nusxasini ishga tushirib tekshirish qiyin — CI uchun **birlik testi** yetarli: `AddStackExchangeRedis` chaqirilishi konfiguratsiya mavjud bo'lganda (`Program.cs` ni qism-test qilish yoki integratsion — Redis konteyner CI'da bo'lsa ikki `WebApplicationFactory` orasida xabar yetishini tekshiring).
- `DistributedCacheTests.cs` (~4): S01.04 `UserStatusCache` va S05.03 dashboard keshi `IDistributedCache` bilan ishlaydi (mavjud testlar `AddDistributedMemoryCache` bilan CI'da Redis'siz yashil qoladi — bu muhim: **haqiqiy Redis CI'da shart emas**).

## 5. Boshlashdan oldin o'qing
`Program.cs` (SignalR va kesh ro'yxatga olish qismlari), `Api/Chat/ChatHub.cs`, S01.04 `UserStatusCache.cs`, S05.03 dashboard kesh joyi, `docker-compose.yml`.
