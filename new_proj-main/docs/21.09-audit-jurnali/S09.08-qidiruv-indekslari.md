## 1. Maqsad
`EF.Functions.ILike(x, "%term%")` indeksdan foydalanmaydi — ~10 000 foydalanuvchida sekinlashadi.

## 2. Hozirgi holat (kodda tekshirilgan)
`PagingExtensions.ContainsPattern` (`Api/Authorization/PagingExtensions.cs`) — `ILIKE '%…%'` qurish (wildcard escape bilan). Ishlatiladigan joylar: `StudentsController.List` (`u.FullName, u.Email, u.Phone, s.StudentNumber`), `LeadsController.List` (`FullName`), `GroupsController` (`Name`), `UsersController.List`, `Api/Search/SearchController.cs` (bir nechta jadval), ehtimol boshqalar — `grep -rn "ContainsPattern" backend/src`.

## 3. Nima qilinadi
- Migratsiya **`AddTrigramIndexes`** (raw SQL, `migrationBuilder.Sql(...)`):
  ```sql
  CREATE EXTENSION IF NOT EXISTS pg_trgm;
  CREATE INDEX CONCURRENTLY IF NOT EXISTS ix_users_fullname_trgm ON users USING gin (full_name gin_trgm_ops);
  CREATE INDEX CONCURRENTLY IF NOT EXISTS ix_users_email_trgm    ON users USING gin (email gin_trgm_ops);
  CREATE INDEX CONCURRENTLY IF NOT EXISTS ix_users_phone_trgm    ON users USING gin (phone gin_trgm_ops);
  CREATE INDEX CONCURRENTLY IF NOT EXISTS ix_leads_fullname_trgm ON leads USING gin (full_name gin_trgm_ops);
  CREATE INDEX CONCURRENTLY IF NOT EXISTS ix_groups_name_trgm    ON groups USING gin (name gin_trgm_ops);
  CREATE INDEX CONCURRENTLY IF NOT EXISTS ix_students_number_trgm ON students USING gin (student_number gin_trgm_ops);
  ```
  ⚠️ `CREATE INDEX CONCURRENTLY` **tranzaksiya ichida ishlamaydi** — EF migratsiyasi standart tranzaksiyada ishlaydi; `migrationBuilder.Sql(...)` dan oldin `Up`/`Down` metodini `[SuppressMessage]` bilan yoki EF Core'ning `MigrationBuilder` uchun tranzaksiyasiz rejimini yoqing (`ActiveProvider` tekshiruvi bilan `context.Database.SetCommandTimeout` va tranzaksiya boshqaruvi — **dotnet-in-docker.sh migration** skripti orqali qanday qo'llanishini oldin tekshiring, kerak bo'lsa oddiy `CREATE INDEX` (tranzaksiyali, dev bazasi kichik bo'lgani uchun qulf muammo emas) ishlatavering va shu qarorni izohga yozing).
  Ustun nomlari real jadval sxemasiga mos ekanini migratsiya yozishdan oldin `Infrastructure/Migrations/AppDbContextModelSnapshot.cs` dan tekshiring (EF `snake_case` yoki `PascalCase` ishlatishi mumkin — loyihadagi konventsiyani ko'ring).
- `ContainsPattern`/`ILike` chaqiruvlarining **o'zi o'zgarmaydi** — Postgres so'rov rejalashtiruvchisi indeksdan avtomatik foydalanadi (`%term%` — GIN trigram indeks buni qo'llab-quvvatlaydi, oddiy B-tree qo'llab-quvvatlamaydi, shuning uchun trigram kerak edi).
- **O'lchash:** dev bazada 180 talaba kam — vaqtinchalik ko'p qatorli jadval (`generate_series` bilan 20 000 soxta foydalanuvchi, migratsiyaga kirmaydi, faqat qo'lda) yaratib `EXPLAIN ANALYZE SELECT … WHERE full_name ILIKE '%ism%'` oldin/keyin solishtiring; natijani (millisekundlarda) `docs/09` ga yozing, keyin soxta qatorlarni o'chiring.
