## 1. Maqsad
TZ §57 **majburiy**: avtomatik PostgreSQL backup, PITR, shifrlangan backup, restore testi, DR hujjati. Hozir **hech biri yo'q**. Ma'lumot yo'qolishi qaytarib bo'lmaydigan zarar — bu qadamsiz real markazga chiqish tavsiya etilmaydi.

## 2. Hozirgi holat (kodda tekshirilgan)
`backend/docker-compose.yml`: `postgres` (`pgvector/pgvector:pg16`), volume `educenter-postgres-pgvector-data` (nomlangan Docker volume, host bekap siyosati yo'q). WAL arxivi, `pg_dump` skripti, backup joyi — hech biri yo'q. Fayllar (`App_Data`, S09.06 dan keyin S3/MinIO) alohida — ular ham backup rejasiga kirishi kerak.

## 3. Nima qilinadi
- **Kunlik mantiqiy backup:** `backend/scripts/backup-db.sh` — `pg_dump -Fc` (custom format, tez restore), fayl nomi `educenter_YYYYMMDD_HHMM.dump`. Cron (host'da yoki alohida `backup` konteyner, `docker-compose.yml` ga profil sifatida — production `docker-compose.prod.yml` alohida fayl, dev compose'ga aralashtirmang).
- **PITR (agar mumkin bo'lsa):** `wal_level = replica`, WAL arxivi (`archive_mode = on`, `archive_command`) → S3/MinIO (S09.06) yoki alohida disk. Boshlang'ich versiyada **pgBackRest** yoki oddiy `pg_basebackup` + WAL arxivi — murakkablik/vaqtga qarab pgBackRest tavsiya (RTO/RPO aniqroq).
- **Shifrlash:** backup fayli `age` (zamonaviy, sodda) yoki `gpg` bilan shifrlanadi, kalit **backup'dan alohida** joyda saqlanadi (parol menejeri/sir do'koni — bu loyihada hali yo'q, hech bo'lmaganda `docs/` da "kalit qayerda saqlanishi kerak" yozilsin, o'zi commit qilinmasin).
- **Uzatish:** backup mahalliy diskdan tashqariga (masalan boshqa server yoki S3 bucket) nusxalanadi — "server o'zi yonib ketsa" stsenariysi uchun.
- **Restore testi (avtomatik, oyda bir marta):** `backend/scripts/restore-test.sh` — eng so'nggi backup'ni **vaqtinchalik** bazaga (`educenter_restore_test`) tiklaydi, tekshiruvlar: jadval soni, asosiy jadvallarda `SELECT count(*)`, `RolePermissionSync` mos ekanligi (S09.01 bo'lsa) — muvaffaqiyatsiz bo'lsa aniq xato bilan chiqadi (kelajakda monitoring/ogohlantirishga ulanadi — hozircha skript exit kodi).
- **DR hujjati — `docs/12_disaster_recovery.md`:** RTO/RPO maqsadlari (masalan RPO ≤ 24 soat kunlik backup bilan, PITR bo'lsa ≤ 5 daqiqa), qadamma-qadam tiklash yo'riqnomasi (server yo'q bo'lganda: yangi Postgres ko'tarish → backup'ni tiklash → `migrate` (S09.01) → `RolePermissionSync` → `App_Data`/S3 tiklash → DNS/konfiguratsiya), kim mas'ul, backup joylashuvi va kalitlar qayerda, oxirgi muvaffaqiyatli restore testi sanasi (skript avtomatik yangilaydigan jurnal fayli yoki qo'lda).
- **Fayllar:** `App_Data` (yoki S09.06 dan keyin MinIO) backup rejasiga kiritiladi — hech bo'lmaganda hujjatda eslatiladi, avtomatlashtirish ixtiyoriy (birinchi versiyada ma'lumot bazasi ustuvor).

## 4. Testlar / tekshiruv
Bu qadam ko'p qismi **infratuzilma skripti**, C# testi emas:
1. `backup-db.sh` ishlab, shifrlangan `.dump.age`/`.dump.gpg` fayl yaratadi. 2. `restore-test.sh` shu faylni `educenter_restore_test` ga tiklaydi, jadval/qator soni asl bazaga mos, muvaffaqiyatli chiqadi.
3. Qasddan buzilgan/noto'g'ri parol bilan shifrlangan fayl → skript aniq xato bilan to'xtaydi (jimgina muvaffaqiyat demaydi). 4. DR hujjatidagi qadamlarni **qo'lda bir marta bajarib ko'ring** (yangi bo'sh Postgres'ga to'liq tiklash) va natijani `docs/09` ga yozing.
