## A. CI pipeline
Hozir `.github/` **yo'q** — 175+ test faqat qo'lda ishga tushiriladi.
- `.github/workflows/ci.yml`: `push`/`pull_request` (`main`) da ikki job:
  - **backend**: `services: postgres: image: pgvector/pgvector:pg16` (env parollar bilan), `actions/setup-dotnet@v4` (.NET 10), `dotnet restore/build/test` (`backend/EduCenter.slnx`), connection string CI Postgres'ga (`ConnectionStrings__Postgres`), `Automation__Enabled=false` (mavjud test konfiguratsiyasi bilan mos).
  - **frontend**: `actions/setup-node@v4`, `npm ci`, `npx tsc --noEmit`, `npx eslint src --max-warnings=0`, `next build` (production build xatosiz bo'lishi).
- Keyinchalik (bu qadamda **yo'q**, faqat eslatma): `docker build` (backend/frontend image), S09.11 e2e testlarini CI'ga ulash.
- **Diqqat:** bu loyihada `dotnet` host'da ishlamaydi (Smart App Control) — bu **faqat shu Windows mashinasiga xos**, GitHub Actions Linux runner'ida muammo yo'q, oddiy `dotnet` buyruqlari ishlaydi (Docker orqali emas).

## C. Hangfire dashboard himoyasi
`/hangfire` faqat `IsDevelopment()` da ochiladi (`Program.cs`), `DevelopmentDashboardAuthorizationFilter` (`Api/Automation/AutomationRunner.cs`) — bearer-token tekshiruvi **yo'q**, faqat muhit filtri. Xuddi shu kod nusxalanib production'ga tushib qolmasligi uchun himoya kerak.
- Yangi `AuthorizedDashboardFilter : IDashboardAuthorizationFilter` — `DashboardContext.GetHttpContext()` dan `Authorization: Bearer` o'qiydi, JWT'ni tekshiradi (xuddi API kabi) va **`system.jobs.view`** ruxsatini talab qiladi (`PermissionResolver.ResolveAsync` to'g'ridan-to'g'ri chaqiriladi — `Api/Search/SearchController.cs` dagi naqsh: policy pipeline'siz ruxsat tekshiruvi).
- `Program.cs`: **Production**da ham `/hangfire` ochiladi, lekin **`AuthorizedDashboardFilter`** bilan (Development'da hozirgidek ochiq qoladi — qulaylik). `S09.01` dagi `StartupValidation` bilan bog'liq emas, mustaqil o'zgarish.
- Dashboard sarlavhasi orqali bearer yuborib bo'lmaydi (brauzer to'g'ridan-to'g'ri ochadi) — **muqobil:** query parametr `?token=` qabul qilib, JWT sifatida tekshirish (SignalR'dagi `access_token` naqshi — `Program.cs` `OnMessageReceived`), yoki alohida qisqa muddatli "dashboard token" endpointi (`GET /api/system/hangfire-token` → `system.jobs.view`, 5 daqiqalik JWT). **Sodda yechim (tavsiya):** ikkinchisi — token URL'da uzoq umr ko'rmasin.
